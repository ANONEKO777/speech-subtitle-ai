# W5 notes: Simplified Chinese, Japanese, the installer and the default language

Branch `pr/P64-i18n-w5`, from `372aad7` (head of `pr/P61-i18n-w4b`). After this round the window speaks four languages, a fresh install follows the operating system, and the Windows installer speaks the same four.

## The catalogs

Every `zh-CN` and `ja` entry was read against the English and the Traditional Chinese, outside the backend messages first and `notices.ts` last, in separate commits (a parallel round edits the zh-TW side of `notices.ts`). Both are still machine translations that no native speaker has read, and the picker says so.

- `zh-CN`: 68 entries changed (39 screens, 29 backend messages). The machine pass already used mainland terms. The changes were words that mean something else on the mainland (项目 for a model row, 配置文件 for a profile, 授权 for a license, 应用 for the app), one wrong meaning (the library's "Add all to play queue" said the batch), and quoted button names that did not match the buttons.
- `ja`: 101 entries changed (80 screens, 21 backend messages). The batch is バッチ so it never reads like the library's 再生キュー, export and import are エクスポート and インポート, a runtime is 実行ファイル on every screen, progress steps are nouns, and wording copied from the Chinese shape was rewritten.
- The glossary has a `zh-CN` and a `ja` column in every table, and its W5 section lists the choices a later wave must keep.
- New keys a later round adds are machine translations again and need the same reading.

## Plurals

`Intl.PluralRules` has only `other` for `zh-CN` and `ja` (and `zh-TW`), so a count of 1 shows the `.other` text and `.one` is never shown. `plurals.cjk.test.ts` pins every plural at 1 in both locales and requires `.one` to equal `.other`. It found one entry, `storage.confirm.body`, that said "them" for 1 model in both locales. The same holds in `zh-TW` (它們 at 1), which this round leaves as it is.

## Release and the default language

- `RELEASED_LOCALES` holds all four. The picker lists 简体中文 and 日本語 with the catalog's "machine translated" note, in the window's language: `日本語 (machine translated)` in English, `日本語（機器翻譯）` in Traditional Chinese.
- `DEFAULT_UI_LANGUAGE` is `auto` in `locale.ts` and `settings.py`. A fresh install, a settings file with no `ui_language` and an empty localStorage mirror follow the system language. A language the app does not speak gets English.
- **Upgrade.** Every build from W0 to W4 wrote `ui_language` into `settings.json` whenever any setting was saved, with the old default `zh-TW`. Such a person keeps Traditional Chinese until they pick another language. Only a settings file with no `ui_language` follows the system.
- **First paint.** The provider resolves `auto` against `navigator.languages` before the backend answers. `I18nProvider.test.tsx` checks the first frame for en-US, zh-TW, zh-CN, ja-JP and fr-FR.
- **macOS.** `app/src-tauri/Info.plist` declares `CFBundleLocalizations` (en, zh-Hant, zh-Hans, ja), which Tauri merges into the bundle. macOS gives an app only the languages it declares, and WKWebView's `navigator.language` follows that choice. Not checked on a Mac.
- **Windows.** WebView2 reports the Windows display language in `navigator.languages`. Not checked on a Japanese or Chinese Windows.
- The Tauri window's own title is still 字幕翻譯 in `tauri.conf.json` until the frontend sets the title in its first effect.

## Fonts

- The old unscoped `:lang(ja)` rule matched every element of a Japanese window, so html, headings, buttons and inputs drew with Yu Gothic UI instead of the `:root:lang(ja)` stack. It is now `[lang]:not(:root):lang(ja)`.
- Text that declares Traditional or Simplified Chinese (a subtitle line, a picker option) takes its script's stack in any window. Before, a Traditional subtitle in a Japanese window took Yu Gothic's Japanese glyph forms, and in a Simplified window YaHei's.
- `fonts.css.test.ts` fails on a `:lang()` selector that is not scoped to the root or to an element that declares its language.

## The installer

- Tauri uses a file named in `customLanguageFiles` instead of its own file for that language. `lang-English.nsh` and `lang-TradChinese.nsh` defined only `deleteAppData`, so the other 26 messages of Tauri's template were unset in both languages: makensis warns 6040 for each, and the text is blank (the desktop shortcut box, the already-installed page, the WebView2 errors). Each file now defines all 27, with `${PRODUCTNAME}` instead of Tauri's `{{product_name}}`.
- `lang-SimpChinese.nsh` and `lang-Japanese.nsh` are new. English is listed first: NSIS shows the system language when it has it and the first listed language otherwise, so an unsupported system gets English, as the window does. There is no language selector.
- `tests/test_installer_languages.py` checks the config and each file's messages, and compiles the four files with makensis (`warning error all`) when makensis is installed.
- Not run: a built installer, on any system language. The macOS bundle has no installer text of its own; the `.dmg` and `.app` carry the plist above.
