# W2 notes: the first-run wizard and the models page

Branch `pr/P54-i18n-w2`, from `main` `ab9b41d`. The wizard, the models table, the delete dialog and the models folder card read the catalog. `zh-TW` is the old text, character for character. `en` is written by hand. `zh-CN` and `ja` are machine translations (marked in each file header, hidden from the picker).

## What was built

- **Catalog areas.** `wizard` (`wizard.*`) and `models` (`models.*`, `delete.*`, `storage.*`) in `app/src/i18n/catalog/<locale>/`. 133 keys in each of the four locales (54 wizard, 79 models). Plural keys: `models.summary`, `storage.confirm.body`, `storage.moving`, `storage.moved`.
- **Helpers.** `stateText`, `shaText`, `forceReasonError` (models page rules), `stateLabel`, `chipOrGpu`, `deviceLabel`, `cpuNotice` and `selfTestText` take a `Translate` with no default now. The W1 constants `PROFILE_NAME`, `PROFILE_BLURB` and `LOCAL_BUILD_*_TEXT` are deleted (their last caller moved). `tZhTW` stays the default only in the areas W3 still owns (`formatEta`, `sourceLabel`, `EXPERIMENTAL*`, `JOB_RUNNING`).
- **Wizard errors.** `WizardState.error` is `string | { assetId, message }` now. A failed download keeps the asset id and the backend message, and the screen words it (`wizard.jobFailed`), so a language switch re-words it. The self-test "no result" case is `error: null` on a `result` step with no test, worded by `wizard.noResult`. This changed one existing assertion in `flow.test.ts` (the state shape, not the text: `error: { assetId: "asset-1", message: "connection lost" }`).
- **Sizes and speeds** (`manage/format.ts`): `bytes`, `mib` and `speed` take the UI locale. The digits still come from `toFixed`, so zh-TW is identical, and only the decimal mark follows `Intl`. All four shipped languages use `.`, so nothing differs today. Callers in this area and `JobRow` and `HardwareSection` pass the locale; W3 callers use the default (zh-TW) and print the same text. There are no dates or ETAs on these screens.
- **Platform-aware example folder.** `storage.placeholder.win` or `.posix`, chosen by W1b's `isMacShell()` (`app/src/platform.ts`), the same check the import box uses. It is synchronous, so the example shows from the first paint, while the settings load and after they fail to load, as zh-TW on `main` always did. Outside the shell it gives the Windows example. A Mac shows `/Volumes/Models/vst-models` (an intended zh-TW change, the Mac models page placeholder only).
- **Guard.** `npm run check:strings` is 251 of 660 (388 after W1, 137 literals removed). No literal is left in `wizard/`, `models-page/`, `manage/`.
- **Row notes** on the models page (verify, repair, refusal) and the working line are kept as data and worded at render, so a language switch re-words them.
- **English wording.** Terms added to `docs/i18n-glossary.md` under "W2". After review: "In use" for 目前使用 in the models table (W1b's term), "Listed version" for 登錄版本. The W1 `localBuild.noUpdate` English now says "Runtimes you build yourself" (it said "Programs", the glossary says runtime).

## Backend and shell text left as it comes (W4)

On the wizard: the profile load error (`fetchProfile` failure, `ApiError` message, English or Chinese as the backend wrote it), the failure message of a download job, the start error (`chooseProfile` or `downloadProfileAssets` failing), the self-test message (including the Visual C++ message below), stage details and fallback reason (shown by `SelfTestPanel`), the `platforms.py` "unsupported platform" text, the `runtimes.py` "no ready-made program, build it here" text, license names and URLs from the registry, the GPU name and driver version, profile `label`.

**The Visual C++ message.** `backend/core/vc_runtime.py` `MESSAGE` (這台電腦缺少 Microsoft Visual C++ 可轉散發套件（x64）…) is raised as `ProbeFailed` by `manager/selftest.py` and shows as the self-test message on the wizard's result step. It is the one Chinese sentence an English Windows user without the VC++ runtime sees on the wizard. W4 should translate it first.

On the models page: the update check `message`, every `UpdateItem.message` (a tooltip), the refusal message and blockers of a delete, verify, repair or download (`refusalOf`), `asset.blockers`, a job's `failure.message`, the repair `action` and `reason` words (`models.repaired*` shows them as the backend sends them), `asset.kind` (`asr`, `llm`, `whisper.cpp`), profile ids in "Used by" (`gpu-24gb`), the storage warnings (`setModelsDir`, `fetchMove`), the move `error`, the inventory and settings load errors, and `runtimes.py` "not removed, found elsewhere" text when it comes back as a refusal.

## Decisions

- The English for `wizard.recommended` is "Recommended profile: **24 GB GPU**. You can also choose one of the other two below." The profile names carry commas ("Apple silicon, 32 GB or more"), so the name goes last, after a colon.
- The partial state is "Incomplete" in English (the chip must stay one short word, "Partly downloaded" widened the Status column).
- `wizard.others.two` and `.three` are "two" and "three" (zh-TW keeps 兩 and 三). A count of one would read "the other 1 profiles". The backend lists three or four profiles, so one cannot happen today.
- Keys that repeat W1 wording on purpose: `wizard.recommendedTag` (zh 建議) next to `hw.recommendedTag`, `wizard.mayNotFit` (zh 這台電腦可能不夠用) next to `hw.mayNotFit` (zh 這台電腦可能不夠). The Chinese differs by one character, so they are not one key.

## Layout

All renders are Edge with a stubbed Tauri and backend (`.work/p54-shots/shots-w2.mjs`), not the Tauri window. Fixes, all scoped with `:root:lang(en)` in `app/src/manage.css`:

- The Visual C++ note is a flex row (icon-less `.note`), so its text, link and tail were three columns. In English it is one block (`.vc-note`). **In zh-TW the note is still three columns (it was before W2).** Fixing it would move zh-TW pixels, so it is left; a one-line follow-up (`display: block` for everyone) would fix it.
- The update line and the size label in the models table may wrap in English, and the Status chip is shorter, so the table fits at 1280 (it scrolled by 22 to 129 px before the fix).
- On the Mac wizard the recommended card's title broke between "32" and "GB", at 960 and at 1280 (the cards are 262 px at both), because the "Recommended" chip shared its row. In English a title that carries a chip may wrap now, so the name stays on one line and the chip drops below it. Titles without a chip are left alone: wrapping them all put the "(parallel)" name under its icon.

**The models table at 960.** The table still scrolls sideways at the minimum window width (zh-TW 240 px, English 258 to 277 px), but the Actions column is sticky on the right (`table.inv .actions-cell`, both languages), so every action button is on screen and the other columns pass under it. A 1 px divider shows only while more table is to the right (`@container scroll-state(scrollable: right)`; an engine without it, such as an older WKWebView, gets the sticky column with no divider). It is a `::before` of the cell: Edge reports a `box-shadow` on a cell of a `border-collapse` table in the computed style and never paints it, so the first version drew nothing. The sticky column changes zh-TW pixels on the models page at 960 only; at 1280 the table does not scroll and the column is not sticky.

**A download's failure in the pinned column.** The backend's SHA256 message holds two 64-character hashes and widened the column from 220 to 408 px, which left Name and 31% of Status in view at 960 and made the table scroll at 1280 (107 px zh-TW, 125 px English). That note has the class `job-failure` now and wraps at 196 px, so the column is 220 px at 960 and 244 px (zh-TW) or 242 px (English) at 1280, with no scroll at 1280. This changes how a zh-TW failure note wraps, at both widths. At 1280 its box is 196 px where it was 220. The cap is not on every row note: the other notes widen the column to 254 px at 1280 on `main` (a long refusal message), and capping them would move those zh-TW pixels. So a row action's refusal with a long unbreakable word would still widen the column. No backend refusal with a hash was found.

**What fails if the sticky column breaks.** In CI, `app/src/models-page/stickyActions.test.tsx` holds the markup (the `.table-wrap` parent, and `actions-cell` on the header and every row, with every button inside). `app/e2e/sticky-actions-css.test.mjs` holds the rule (`container-type`, `sticky`, `right: 0` and a background in both blocks, the `::before` divider inside the `scrollable: right` block, the failure note's cap, and the wizard title's wrap). Neither one lays anything out or paints it. The real proof is an Edge rectangle assertion over the render logs (`.work/p54-final/assert-sticky.py`, not in CI): no action button outside the visible table area. All four CI checks and the Edge assertion fail on `0127b80`, the head before the fix (at 960, 26 of 26 buttons outside on Windows and 8 of 8 on the Mac, in both languages). After the merge of W3a: 0 of 798 buttons outside in each language, at 960 and 1280.

The divider was proved on painted pixels in Edge, by screenshot pairs with the rule on and forced off (`.work/p54-fix2/probe.mjs` and `divider.py`, not in CI): at 960 one pixel column changes at the cell's left edge in both languages, (46, 46, 49) in zh-TW and (47, 47, 49) in English against the surface's (18, 18, 21), and nothing changes there at the far end of the scroll or anywhere at 1280.
