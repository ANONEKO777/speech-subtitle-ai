# W4b part 1: the English backend messages a Traditional Chinese window shows most

Branch `pr/P61-i18n-w4b`, from `96dc7b3` (head of `pr/P60-i18n-w4a`). It covers groups 1 to 6 of the table in `w4a.md`. Groups 7 to 14 are a later round. 129 new codes are worded in the four catalogs. `zh-CN` and `ja` are machine translations, as the rest of those catalogs are.

The English is what `96dc7b3` sent, except where it was wrong: `the queue crashed` is now `the batch crashed`, because the window says batch, and the fix round below changed three more (a runtime row's update note, a program that exits with no output, a key no header can carry), and the second fix round one more (the update note of a runtime built on the machine). `tests/notice_scenarios_w4b.py` raises the sentences at the site the app raises them (147 scenarios, all 137 codes). It was run on a clean export of `96dc7b3`, and that output is the `before` field of `notices.w4b.fixture.json`. The vitest requires the English the window shows to equal `before`, and the Traditional Chinese to equal the reviewed `zh` field.

## What changed in the structure

W4a's recipe holds. Three fields gained notices:

| Channel | Text | Notices |
|---|---|---|
| `/api/profile` | `recommended.why` | `why_notices` |
| `/api/updates/check` | `message`, `items[].message` | `message_notices` on each |
| download job | `failure.message` | `failure.message_notices` |
| the 409 for a file another program holds | `detail.message` | `notices`, beside `detail` |

None of these is stored. `selftest.json` and `queue.db` hold new codes in the fields W4a added, so an earlier build reads them as before. A W4a build shows a code it does not know in English. No key was added to `project.json`.

**Whole sentences.** Substring replacement cannot word a sentence assembled from fragments, so these senders now send whole sentences:

- The "why" block was a label followed by a reason or a stage description. Each line is now one notice. A profile's name is a second notice, listed after the line that quotes it, and `Profile.label` takes its text from that notice.
- Two self-test messages joined two sentences (`reason + " The CPU self-test passed."`). Each is now one template, so Chinese gets no space after `。`.
- The locked-file sentence chose its subject from three fragments. It is three templates.
- The default ffmpeg detail and the engine's "no output" detail were fragments. Each has its own template.

**Quoting.** The interrupted download and the mixed-language refusal take the quoted sentence as a text parameter. The quoted sentence is a notice of its own, listed after the wrapper.

**The self-test's failures** are a `clauses` parameter: a list of the failed stages, each a notice of its own (`selftest.asrFailed`, `selftest.llmFailed`) that quotes what the stage said. The window joins the list with `common.clauseSeparator` (`; ` in English, `；` in Chinese), so no ASCII `: ` or `; ` is left inside a Chinese sentence. The stage notices come before the notices they quote, because two stages can quote the same sentence and the window replaces every copy at once. In `zh-TW` each wrapper says what happened first and ends with 失敗原因：{failures}. `word()` drops a `；` or `。` that follows a quoted sentence's own `。`, so a stage that quotes a whole sentence (the Visual C++ one) gives no `。；` or `。。`. A program that exits with no output says so (`selftest.exitedSilent`) instead of leaving a colon with nothing after it, in both languages.

**The API key.** The window receives a notice's parameters beside the text. `llm/client.py` therefore redacts the key from every parameter, not only from the finished sentence. `_fail` takes a template, so the chat client cannot send an unredacted sentence through it. `redact()` matches the key in any mix of the spellings a server can echo it in: as sent, percent-encoded in either case, JSON-escaped (an escaped slash, or a character as a Unicode escape, even with the backslash doubled), and as HTML entities. An error body is read only to 4096 bytes, so a key cut off at the end of that read also loses a piece of 8 or more characters. The connection test in Settings uses the same `redact()`. A key that holds a space, a line break or any character outside printable ASCII is refused when the client is configured (`llm.keyUnsendable`), with no piece of the key in the text. Before, it went to the first request and failed in `http.client` with the whole key in the error. Settings and a run drop the spaces and line breaks around a saved key, so a pasted key with a trailing space still works. A server's own masked echo (`sk-INVEN****zzQQ`) is shown as the server sent it.

## The guard

`tests/test_notices_guard.py` reads 21 backend files. It fails on an English sentence of two words or more in a raised error, in a download failure, in a returned value, or in a variable named like a message. Sentences the window never shows are listed with their reason, and a listing that matches nothing also fails. On `96dc7b3` it reports 93 sentences.

It does not see a sentence passed to a call it does not know (the batch's `skipped` list, the download's retry note), a sentence inside a `ValueError`, a one-word message, or a file outside its list.

## Where the W4a table differs from the code

- **The download retry note is never rendered.** The window parses `note` into `DownloadJob`, and no component reads it. It has no code. A change that shows it needs `note_notices`.
- **"a job is already running" never reaches the window.** `startJob` replaces every 409 from the jobs route with `errors.jobRunning`. No code.
- **`cue N could not be translated` is not reachable from the window.** The pipeline passes `keep_english=True`, so only the command line gets `TranslationError`. It has a code anyway.
- **A stage that passed shows no note.** `SelfTestPanel` shows `detail` for a failed stage only. The three success notes have codes because the report holds them.
- **Missed by the table, and now coded:** the other self-test failures (a program that cannot start, hangs or exits), the four ways a remote registry cannot be read (a 502 on the update check), the archive errors of a download, the 409 for a locked file, the WAV and engine output errors, the summary errors, and the saved API key that cannot be read.

## English that a Traditional Chinese window can still show in these places

- **Prefixes.** A job's error starts with its step (`asr: `), and a batch row's with the error's class (`OptionsError: `). W4a kept these, and so does this round.
- **Names.** Profile, model and runtime ids, engine names, `cuda`/`cpu`/`metal`, the summary's call labels (`map 1/1`, `reduce zh-TW`), and command-line flags.
- **Other programs and the system, as detail.** ffmpeg and ffprobe stderr, a program's last output lines, OS error text, Python's JSON and WAV errors, HTTP reason phrases, and an LLM server's error body.
- **The app's own English, quoted as detail.** This is not third-party text:
  - the reason a model's reply was rejected (`ReplyError`), inside `summary.notWritten` and `translate.cueFailed`. The same words go back to the model. `zh-TW` puts both details of `summary.notWritten` in 「」, so they read as quoted. When the server failed after a rejected reply, the reason is the server's error, which has its own code: `ask()` raises `RepliesRejected` from the error that gave its reason, so the window words it;
  - the error of a damaged subtitle file (`core/subtitle_io.py`), inside `translate.cannotResume`;
  - the API key store's own errors (`manager/secrets.py`, such as `Windows DPAPI failed (error N)`), inside `resolve.keyUnreadable`. This belongs with group 9.
- **Not coded, outside the six groups or very unlikely:**
  - `core/model.py`, `core/artifacts.py` and `core/subtitle_io.py`: a damaged file in a project folder;
  - `core/vad.py`: the VAD model deleted between the check before a run and the run;
  - `manager/runtimes.py`: installing an add-on by itself;
  - `api/inventory.py`: `nothing to update for ...`, which the window only reaches if the list is stale;
  - `llm/client.py` and `api/jobs.py` validation of a request the window does not send;
  - a locked file inside a delete refusal (group 8) or a models move (group 10). Only the outer 409 route has the notice.

## Second fix round after the delta FAIL at `1acc87d`

**The redactor no longer builds a regex the length of the key.** The cut-prefix pattern nested one optional group per key character, and Python's regex parser raised `RecursionError` for keys over about 500 characters. Every HTTP error then became "maximum recursion depth exceeded", which `ask()` does not retry. A flat pattern fixed the recursion but still took about 2 s to compile for a 10,000-character key. `redact` now finds where the key's first 8 characters appear with a small regex, and walks the key one character at a time from each place. The walk keeps every text position it can reach, because a key's `%`, `\` or `&` can be read as itself or as the start of an escape. On a 4 KB body that echoes a random 10,000-character key, a cold call takes 6.9 ms. A body with no echo takes 0.3 ms. One case is slow: a key of one repeated character against a body of that character takes seconds, because every place starts a long walk. Real keys are random, so this case does not happen with them.

**A cut inside an encoded character** (`%3`, `\u00`, `&#4`) now counts as the end of the text, so the key prefix before it is redacted.

**A runtime built on the machine** gets its own update note, which names the build script (`updates.localBuild`). One found on PATH or in Homebrew gets `updates.localBuildElsewhere`, which does not send it to the script, because the script would build a second copy. This matches the version cell, which already said this. Both items are no longer installable. The glossary says 自行建置 and never "compile", so the Chinese does not use 編譯 as the verifier suggested.

**Settings refuse a key with a space or another character no header can carry** when the key is saved or tested. Both routes answer 422 with `llm.keyUnsendable`, and the LLM page words it beside its buttons.
